## 1. ゲームループとステート遷移の鉄則

アドベンチャーゲームおよびノベルゲームにおける最大の致命的欠陥は、**「プレイヤーが意図しない不可逆遷移によって進行不能（デッドロック／詰み）になること」**である。

### 1-1. 不可逆遷移の禁止（いつでも現場調査に戻れる可逆性）
- **探索パートから立証・論戦・協議パートへの遷移**:
  - 探索から立証に進んだ後でも、立証画面内に**「🔍 現場の再調査に戻る」ボタン**を常備すること。
  - ショートカットキー（`B` キーまたは `Esc` キー）でも即座に探索画面へ戻れるようにする。
- **ゲームオーバー時の復帰ルート**:
  - ライフが0になりゲームオーバーになった際、「立証のリトライ」だけでなく、**「🔍 現場の再調査に戻る（探索再開）」ボタン**を必ず提供すること。
  - 必要な証拠品が不足している状態で立証に進んで敗北した場合、リトライしか選べないと完全に詰むため、現場で証拠を探し直せる導線を絶対に断ってはならない。
  - 探索復帰時はライフを最大値に回復させ、BGMを探索曲に戻すこと。

### 1-2. 前提条件とボタンのアクティブ制御（Condition Lock）
- **前提条件未達時のアクション禁止**:
  - 立証・反証に必要な証拠（最低3件など）が揃っていない段階では、立証へ進むボタンを**非表示（`hidden`）**にするか、明確に**非活性（`disabled`）**とすること。
  - 証拠が0件の初期状態から「反証へ進む！」ボタンが表示されていたり、押せてしまったりする状態は重大なバグである。
- **ロジック層での二重安全ガード**:
  - UI上でボタンが押せた場合でも、ロジック側（`startDebate()` 等）の冒頭で手持ち証拠数を検証し、不足している場合は警告アラートを表示して処理を安全に中断すること。
  ```javascript
  if (this.state.collectedEvidence.size < requiredCount) {
    this.audio.playWrong();
    alert('【証拠不足】相手に反証するには、あと○件の鑑識データが必要です！現場を調査してください。');
    return;
  }
  ```

### 1-3. 一時ステートと永続セーブデータの明確な分離
- **一時ステート（Transient State）**:
  - 現在のライフ、所持証拠セット、現在の問答ステップ、探索中のエリア等はプレイ毎に管理し、ゲーム開始時（プロローグ開始時）に必ず `resetTransientState()` で初期化する。
- **永続ステート（Persistent State）**:
  - 1周目クリア実績（`hasClearedLoop1`）、トゥルーエンド実績（`hasClearedTrueEnd`）、オーディオ設定（ボイス/SE/BGM）は `localStorage` に保存。
  - データ初期化ボタン（`btnResetSave`）で永続データを消去した際は、一時ステートも同時にクリーンにし、画面の表示を即時更新すること。

## 2. 物語体験とカタルシスの設計

プレイヤーが推理を巡らせて証拠を見つけ、相手の誤認や疑惑を打破したとき、そこには**「正当な物語的報酬（カタルシスとドラマ）」**が必須である。

### 2-1. 勝利直後の理不尽な突き落としの禁止
- **成功に対する正当なフィードバック**:
  - プレイヤーが正しい証拠を突きつけて立証に成功した直後に、理由もなくいきなり「BAD END（逮捕・押収）」に突き落としてはならない。
  - 1周目で完全な真相に辿り着かない構成であっても、まずは**「主人公の潔白の証明」「仕事PCや機材の押収阻止」「捜査官の職務的納得」「住民や仲間からの感謝と安堵」**という一次解決のエピローグ会話劇を必ず描くこと。
- **段階的解決（NORMAL END）から深層真実（Phase 2）への接続**:
  - 1周目クリアは『NORMAL END: 第一幕完結 〜事件解決、そして解けない謎〜』とし、主人公の日常は守られたが「なぜあの怪現象が起きたのか」という謎が残る形で締めくくる。
  - その上で、翌朝のスマートフォンに届いた謎のパケットや電脳ログをきっかけに、プレイヤー自らが真相を解き明かす「Phase 2（深層解決編）」へと自然に誘導する。

### 2-2. 敗北時・ゲームオーバー時の納得感
- ゲームオーバー画面では、単に「ゲームオーバー」と表示するのではなく、**「なぜ相手を納得させられなかったのか」「どの証拠の着眼点を見落としていたのか」**を振り返られるテキストを提示すること。

## 3. UI/UXとレスポンシブデザイン

ノベルゲームは、プレイヤーがスマートフォンを片手（親指）で操作しながら、あるいはPCでじっくりとテキストを読み進めるゲームである。あらゆる画面サイズで美しく、押しやすく、破綻しない設計が求められる。

### 3-1. スマートフォンでのカットイン・ダイアログ見切れ防止
- **固定ピクセル（px）の全廃**:
  - カットインテキストやダイアログのタイトルには `font-size: clamp(...)` を使用し、極小スマホ（幅360px〜380px）からデスクトップ（1920px+）まで自動スケールさせる。
  ```css
  /* 例: 異議ありカットインのレスポンシブ文字 */
  .cutin-text {
    font-size: clamp(1.2rem, 5.8vw, 2.5rem);
    white-space: nowrap;
    letter-spacing: 0.04em;
  }
  ```
- **ボックスモデルと傾斜アニメーションの余白計算**:
  - `.cutin-box` 等のバナーコンテナには `width: 92vw; max-width: 520px; box-sizing: border-box;` を指定。
  - `transform: skew(-6deg)` やズームアニメーション（`scale(1.05)`）をかけても、画面の左右端を突き破って文字が欠けないよう、左右パディングとビューポート幅の比率を厳密に計算する。

### 3-2. 会話ノベルウィンドウの画面下端見切れ防止（Mobile Viewport & Safe Area）
ノベルゲームの根幹である「会話テキスト」と「ノベルウィンドウ」が、スマートフォンの動的アドレスバーや画面下部システムジェスチャーバーで見切れる問題を防ぐため、以下の規約を徹底する。

- **動的ビューポート高（`100dvh`）の使用と `100vh` 重複指定の禁止**:
  - モバイルブラウザ（Chrome/Safari）ではURLバーやツールバーの開閉により、CSSの `100vh` は常に実際の可視領域より約50px〜70px大きくなり、画面下端が見切れる原因となる。
  - `body`、`#game-container`、`.dialogue-stage`、`.modal` には `min-height: 100dvh;`（および `height: 100dvh;`）を指定すること。なお、同一ルールブロック内に `min-height: 100vh; min-height: 100dvh;` を重複記述すると静的解析（SonarQube S4656 / Biome `noDuplicateProperties`）違反となるため、`100dvh` に一本化すること。
- **会話ステージ（`.dialogue-stage`）の `position: fixed` 必須化**:
  - 会話レイヤーを背景コンテンツ（探索画面や立証画面）の内部に `position: absolute` で配置すると、背景コンテンツの高さやスクロール位置によって会話ウィンドウが画面外へ押し出される。
  - 会話ステージは必ずビューポートに対して `position: fixed; top: 0; bottom: 0; left: 50%; transform: translateX(-50%); width: 100%; max-width: 960px; height: 100dvh; z-index: 45;` で配置し、画面下部に常時固定すること。
- **セーフエリア（Safe Area Insets）と `viewport-fit=cover`**:
  - HTMLヘッダーに必ず `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">` を指定。
  - ノベルウィンドウ下部には、iOSホームインジケータやAndroidジェスチャーバーと重ならないよう、`margin-bottom: calc(8px + env(safe-area-inset-bottom, 0px));` および `padding-bottom: calc(10px + env(safe-area-inset-bottom, 0px));` を設定する。
- **文字サイズ・行高・ボックスのレスポンシブ制限**:
  - 会話文（`.dialogue-body`）は `font-size: clamp(0.82rem, 3.8vw, 0.92rem); line-height: 1.5; overflow-wrap: break-word;` で制御し、2行〜4行のセリフでも突き破らないようにする（非推奨の `word-break: break-word;` は SonarQube S1874 違反のため使用禁止）。
  - ノベルウィンドウ（`.novel-window`）には `max-height: 38dvh;` を設定し、画面の4割以上を占有してキャラクター立ち絵を覆い隠さないようにする。
- **探索ステージ（`.explore-stage`）の縦幅適正化**:
  - デスクトップ用の固定高（例: `height: 520px`）がモバイルで残っていると背後コンテナが肥大化するため、モバイル時は `height: auto; max-height: 50dvh; aspect-ratio: 4 / 3;` で適正サイズに制御する。

### 3-3. 探索ピンの重なり防止（Zero-Overlap Pin Layout）
- **ピン同士の十分な距離（分散配置）**:
  - 探索画面で複数のアイテムやスポットが近接していると、ピンアイコンや `.pin-label` が折り重なり、後ろのピンがタップできなくなる。
  - 各スポットの座標（`coords: { x, y }`）は、同一エリア内でユークリッド距離にして最低 **20%以上** 離すこと。
  - 特に**同一直線上（垂直・水平方向の同一列）への配置を厳禁**とする（縦並びの場合、高さ70px以上のピン同士が衝突する）。
  - 端の境界マージンを確保するため、座標は `x: 15%〜86%`、`y: 20%〜82%` の範囲に収め、画面外への突き抜けや見切れを防止する。
  - 2周目以降で追加される隠しスポットも、1周目の既存ピンと被らない別領域（棚上、PCデスク、窓際、サブ端末等）に配置する。
- **簡潔なピン名と折り返し制御**:
  - ピンラベル（`.pin-label`）は5〜9文字程度の簡潔な名詞（「TVボックス」「Wi-Fiルーター」等）とし、`white-space: nowrap;` で制御する（冗長な名称による画面圧迫と不自然な縦改行を防止）。
- **バッジのアンカー固定（`.pin-icon-wrap`）**:
  - `NEW` や `TALK` などの状態バッジは、横幅が可変する `.explore-pin` 全体ではなく、常に一定サイズのアイコン直上（`.pin-icon-wrap`）に相対配置する。
- **ピンのCSS制御**:
  ```css
  .explore-pin {
    position: absolute;
    transform: translate(-50%, -50%);
    display: flex;
    flex-direction: column;
    align-items: center;
    width: max-content; /* 親の残り幅による自動縮小を抑止 */
    max-width: 130px;
    z-index: 10;
    touch-action: manipulation;
  }
  .pin-icon-wrap {
    position: relative;
    display: inline-flex;
    align-items: center;
    justify-content: center;
  }
  .pin-status-badge {
    position: absolute;
    top: -4px;
    right: -6px;
    white-space: nowrap;
    z-index: 5;
    pointer-events: none;
  }
  .pin-label {
    margin-top: 4px;
    font-size: 0.72rem;
    font-weight: 700;
    background: rgba(3, 7, 18, 0.92);
    border: 1px solid rgba(0, 243, 255, 0.35);
    padding: 2px 8px;
    border-radius: 8px;
    white-space: nowrap;
    text-align: center;
    line-height: 1.3;
    pointer-events: none;
  }
  ```

### 3-4. タッチターゲットのサイズ（モバイルアクセシビリティ）
- ボタンやピンアイコンのタップ領域は、Apple iOS HIGおよびGoogle Material Designの基準に基づき、最低 **44px × 44px（推奨 48px × 48px）** を確保すること。

## 4. ノベルゲーム必須機能の実装基準

Webノベルゲームとしてプレイヤーがストレスなく読み進めるための機能セットを確実に実装・維持すること。

| 機能 | 仕様要件 |
| :--- | :--- |
| **オートモード (AUTO)** | 次のテキストへ一定時間（文字数に応じた可変ディレイ、約1.5〜3秒）で自動進行。画面タップや選択肢出現時に安全に一時停止・解除。 |
| **スキップモード (SKIP)** | 既読・未読を問わず高速でテキストを送る。選択肢出現時や重要イベント発生時に自動停止。 |
| **バックログ (LOG)** | 過去の発言者名とテキストをスクロールリストで閲覧可能。最新の発話が一番下に表示され、自動で最下部へスクロール。 |
| **音声・SE・BGMトグル** | 音声読み上げ、効果音、BGMを個別にON/OFF可能。設定は `localStorage` に保持。 |
| **タイピング演出** | 1文字ずつタイプライター風に表示。表示途中に画面をクリックした場合は即座に全文を表示し、次クリックで次の行へ進む。 |
| **キーボードショートカット** | `Space` / `Enter`（送り・決定）、`Tab` / `← →`（エリア切替）、`1〜9`（選択肢・証拠選択）、`E`（証拠手帳）、`L`（ログ）、`Esc` / `B`（閉じる・探索復帰）。 |

## 5. CSSとフロントエンド実装の規約

### 5-1. グローバル `.hidden` ルールと CSS 詳細度（Specificity）設計（`!important` 禁止）
SonarQube 品質基準（S9423）に基づき、CSS における `!important` の使用は全面禁止である。IDセレクタやコンポーネントクラスに対して `.hidden` を確実に効かせるため、以下の2原則を徹底すること：
1. レイアウトの `display: flex` 等は可能な限りクラスセレクタ（`.hud`、`.choice-stage` 等）に定義し、IDセレクタ（`#hud`）への直接 `display` 指定を避ける。
2. スタイルシートの最上部で、主要なID・クラスと組み合わせた複合 `.hidden` セレクタを一括定義する。
```css
/* 汎用非表示クラス（詳細度制御により !important なしで確実に非表示） */
.hidden,
#hud.hidden,
.hud.hidden,
#choice-stage.hidden,
.modal-overlay.hidden {
  display: none;
}
```
また、スタイル改修時はファイル末尾に上書きパッチセクションを追加するのではなく、既存の正規ルールブロックを直接更新して単一定義（Single Source of Truth）を維持すること。

### 5-2. アニメーションのリフロー再トリガー
カットインや点滅などのCSSアニメーションをJavaScriptから複数回呼び出す場合は、クラスの付け替えだけでなく、必ずリフロー（再描画）を発生させてアニメーションの再発火を保証すること。
```javascript
// アニメーションを確実に再発火させる記述パターン
this.dom.overlayCutin.classList.remove('hidden');
this.dom.overlayCutin.classList.remove('active');
void this.dom.overlayCutin.offsetWidth; // リフローを強制
this.dom.overlayCutin.classList.add('active');
```

### 5-3. キャッシュバスターの管理
HTMLファイル内のCSSおよびJS読み込みタグには、ファイル修正時に必ずバージョンパラメータを付与・更新すること（例: `?v=20261015_rev1`）。ブラウザキャッシュによる新旧スクリプトの不整合を防ぐ。

## 6. 総合検証チェックリスト（リリース・改修時の20項目）

コードの変更を行った後は、必ず以下の20項目を実機またはブラウザ開発者ツール（デスクトップ ＆ 幅375pxスマホ）で検証すること。

### 【ゲームループ・進行】
- [ ] 1. ゲーム起動時（証拠0件）の探索画面で、立証・反証ボタンが一切表示されていないこと。
- [ ] 2. 証拠が規定数未満の状態で立証画面へ進むことができず、安全にブロックされること。
- [ ] 3. 規定数の証拠を集めた瞬間に、立証ボタンが視覚的演出（発光・出現）と共に活性化すること。
- [ ] 4. 立証画面へ進んだ後、「現場の再調査に戻る」ボタン（および `B` / `Esc` キー）でいつでも探索画面に戻れること。
- [ ] 5. 立証で不正解になりゲームオーバーになった際、「現場の再調査に戻る」ボタンで探索画面に戻って証拠を探し直せること。
- [ ] 6. 立証で全問正解した後、唐突なゲームオーバーにならず、事件解決のエピローグ会話劇が再生されること。
- [ ] 7. 1周目クリア時に「第一幕完結（NORMAL END）」を迎え、2周目（Phase 2: 深層解決編）への案内が表示されること。
- [ ] 8. 2周目で真実を証明した際、共生プロトコル締結のエピローグを経て「TRUE END」に到達すること。

### 【UI・レスポンシブ・操作性】
- [ ] 9. 幅360px〜380pxのスマートフォン画面で、カットイン（「客観的反証があります！」）の文字や枠線が画面外に見切れないこと。
- [ ] 10. 幅360px〜380pxのスマートフォン画面（動的アドレスバー・ジェスチャーバー環境）で、会話ノベルウィンドウ、話者名、テキスト、AUTO/SKIP/LOGボタン、送りプロンプト（▼）が画面下端に見切れないこと。
- [ ] 11. 探索画面内のすべてのピンが重ならず、指でスムーズにタップできること。
- [ ] 12. 2周目追加ピンも1周目のピンと被らず、独立した家具・設備の位置に配置されていること。
- [ ] 13. 証拠手帳モーダル、バックログモーダルが正しく開き、右上の「✕」や背景タップ、`Esc` キーで閉じられること。
- [ ] 14. HUDのライフ（ハート）、現在エリア、Phase表示が正しく更新されること。

### 【演出・ノベル機能】
- [ ] 15. テキストタイピング演出中にタップすると、即座に全文が表示されること。
- [ ] 16. AUTOモードをONにすると自動でテキストが進み、画面タップで解除できること。
- [ ] 17. SKIPモードをONにすると高速で送られ、選択肢で安全に停止すること。
- [ ] 18. 音声、SE、BGMのON/OFFが正しく機能し、ページリロード後も設定が保持されること。
