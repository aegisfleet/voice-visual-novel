# BGM制作ガイドライン（生成・ループ加工・再生の標準方針）

本ドキュメントは、本リポジトリの全タイトル（PROJECT EVE / BOX WORM / GHOST SCHEMA / 今後の新規タイトル）で BGM を新規生成・差し替える際の標準手順を定める。2026-10-26 の GHOST SCHEMA の BGM 差し替えで実測・検証した方法を一般化したもので、BGM 作業を行うエージェント・開発者は本書を必読とする。

## 1. 基本方針

1. **生成は「長めに作って切り出す」前提**。AI 音楽生成（Lyria 3 / Flow Music 等）は BPM・尺の指定を厳密には守らない（実測では約1分指定で約3分が生成され、テンポも指定とずれた）。プロンプトにはインストゥルメンタルであること、BPM の目安、ループ用途、不要な要素（ボーカル等）を明記するが、最終判断は必ず実測で行う。
2. **継ぎ目の良し悪しは波形だけでは決まらない**。サンプル段差が最小の切り方が、和音のつながりでは最悪だった事例がある（末尾と先頭で調域が飛ぶ）。波形指標と記号解析（メロディ・和音）の両方で検証してから採用する。
3. **最終判断は人の試聴**。自動計測は候補の絞り込みと不採用判断のための補助であり、「綺麗に聞こえるか」は人間が聴いて決める。

## 2. ループ加工の標準手順

### 2.1 テンポとグリッドの実測
- 生成曲のテンポは指定値を信用せず、オンセット自己相関やビートトラッキングで実測し、その拍グリッドを全ての切り出しの基準にする。
- 切り出しは小節単位（拍の整数倍）で行い、拍の途中では切らない。

### 2.2 区間の選択
- 音量・音色が安定した区間を選ぶ。イントロのビルドアップ、セクション変化、フェードアウトは原則として避ける。
- **区間の長さはコード進行の周期に合わせる**。末尾の和音が先頭の和音へ自然に戻る（循環する）長さにしないと、波形がどれだけ滑らかでも「曲が途中で別物になる」違和感が残る。周期は 2.3 の記号解析で特定する。

### 2.3 記号解析による検証（必須）
波形指標に加えて、以下を測って候補を採点する。

- **クロマ（音高クラス）の後続妥当性**: 元曲全体で「末尾の小節に似た和音の次に来る小節」を探し、先頭の小節がその分布に近いかを見る（follower 妥当性）。あわせて末尾→先頭のクロマ距離を、曲内の通常の小節遷移の分布（中央値・パーセンタイル）と比較し、極端な外れ値の候補は採用しない。
- **ノート列の確認**: Basic Pitch 等で音声を MIDI 化し、(a) 先頭と末尾の支配的な音高クラス（≒調域）が循環するか、(b) 切り出し境界をまたいで鳴っているノートが最小限か、を確認する。密集したミックスでは個々のノートに誤検出が混ざるため、単音ではなく音高クラスの分布で判断する。
- **拍位相**: 境界が拍・小節頭に一致していること。位相の微調整（数百 ms 級）を波形相関で行う場合は、和音の整合を壊さない範囲に留める。

### 2.4 継ぎ目の加工
- 基本は末尾→先頭への**等パワークロスフェード**。長さの目安は、リズムのある BGM で 50〜200ms、アンビエントで 500〜2000ms。拍単位（数百 ms〜秒級）の長いクロスフェードは、位相のずれたリズム同士が重なって濁るため避ける。
- **「無音でつなぐ」構成も選択肢**。曲頭（無音から開始）や曲尾フェード（無音へ収束）など、本当に静かな箇所同士を接続できれば、継ぎ目は最も目立たない。ただし本編が均一に大きい曲には静かな箇所が存在しないことが多いので、実測してから判断する（GHOST SCHEMA の truth はこの方式で全編アーク構成とした）。
- 静かな区間だけでループを作る場合は注意する。ラウドネス正規化で全体が持ち上がり、「無音→急な開始」になって本末転倒になることがある。音量設計は完成ファイルの実測で判断する。

### 2.5 仕上げと検証
- 仕上げは **-16 LUFS / トゥルーピーク -1.5 / MP3 192kbps / 48kHz** を標準とする（タイトル内で基準を統一する場合はそちらを優先）。
- **検証は必ず納品 MP3 をデコードして測る**。エンコード前の WAV の指標は当てにならない（短いクロスフェードは MP3 化で段差が増えることも実測済み）。測る項目: 継ぎ目のサンプル段差（通常の隣接サンプル差との比較）、前後 200ms の音量比、スペクトル不連続比、頭尾の無音時間（意図した無音接続の場合を除き 0ms が目標）。

## 3. 再生方式の標準

- BGM は Web Audio API で再生する。`fetch` + `decodeAudioData` で `AudioBuffer` 化し、`AudioBufferSourceNode`（`loop=true`、`loopEnd=buffer.duration`）で**サンプル精度のギャップレスループ**とする。`HTMLAudioElement` の `loop` はシーク境界で一瞬の無音が生じるため、フォールバック専用とする。
- 曲切替の非同期競合（古いロード結果が後から再生される等）はセッション ID 等で防止し、音量は `GainNode` で制御する。画面が非表示になったら `AudioContext` を suspend し、復帰時に resume する。
- **セリフボイスの経路とは分離する**。ボイスは AGENTS.md の「同期直接再生パイプライン」を維持し、BGM 側の都合（Web Speech の可否判定等）でボイスを止めない。
- 既存タイトルで再生方式が異なる場合は、そのタイトルの BGM を更新するタイミングで本方式へ寄せる。

## 4. 受け入れチェックリスト

- [ ] 拍・小節グリッドに一致した切り出しになっている
- [ ] クロマの後続妥当性が曲内の通常遷移の範囲内（極端な外れ値でない）
- [ ] 先頭と末尾の調域が循環し、境界をまたぐノートが最小限
- [ ] 納品 MP3（デコード後）で段差・音量比・スペクトル不連続が通常部と同水準、不要な無音がない
- [ ] ラウドネスがタイトル内の基準（標準 -16 LUFS）に揃っている
- [ ] Web Audio 経路で再生が開始し、曲切替・非表示/復帰が正常に動く（PC とスマホ幅で確認）
- [ ] 人が試聴して継ぎ目が気にならない
- [ ] 対象タイトルの README 等に、生成曲・加工方法・ループ尺を記録した

## 5. 実装メモ（検証済みツール構成）

- 解析: Python + librosa（クロマ・ビート）、Basic Pitch（音声→MIDI）。Basic Pitch は Python 3.11 系 + `numpy==1.26.4` + `setuptools<81` のピン留めが必要（Python 3.12 や NumPy 2.x では import が壊れることを実測）。
- 加工: ffmpeg（等パワークロスフェード相当の折り畳み合成、二段階 loudnorm、MP3 エンコード）。
- GHOST SCHEMA での適用記録は `ghost/README.md` の「BGM（シーン別4曲）とループ設計」を参照。
